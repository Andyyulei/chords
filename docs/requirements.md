# 和弦进行与 Voicing 练习材料生成器：计划书与要件定义

版本：v1.0 · 2026-11-13（Asia/Tokyo）  
用途：交给 Codex 或其他开发 Agent，独立实现可运行的第一版 Web 应用。  
暂定英文项目名：Voicing Studio；中文工作名：和弦练习工坊。名称可更换。

## 0. 如何使用这份文档

本文同时包含产品目标、功能要件、音乐规则、数据结构建议、实施计划与验收条件。第 19 节是一段可以直接复制给 Codex 的执行指令。

本轮只要求实现本地可运行应用，不要求公开部署、付费服务、创建远程仓库或发布到应用商店。

## 1. 产品目的与目标用户

目标用户是希望用吉他、钢琴为自己伴唱与写曲的 singer-songwriter。用户关注和弦进行、不同的和弦色彩、具体配音与把位，无须先找到某一首现成歌曲。

用户目前的主要麻烦是：看到一个想练的进行，需要分别寻找弹法、手画和弦图；想改一个 voicing，又需要重新整理练习材料。

应用让用户从罗马数字级数出发，选定调性及和弦性质，挑选并编辑吉他和钢琴 voicing，最终得到清晰、准确、可保存和打印的一组图。

典型结果：四个和弦，每个和弦一张吉他图与一张钢琴图，共八张图。每张图能说明实际弹哪些音，以及这些音相对当前和弦根音的角色。

用户可以长期积累很多进行和演奏版本；第一版只需支持材料的创建与管理，不构建学习课程或练习调度。

## 2. 已确认的产品边界

### 2.1 必须实现

1. 从预置或自定义的级数进行开始。
2. 选择 Key，转换成实际和弦。
3. 设置每个和弦的性质，例如 minor、maj7、m7、7、6、m6、9、m9、maj9。
4. 对同一个和弦分别选择吉他与钢琴 voicing。
5. 在图上直接编辑弹法。编辑器是核心功能，不能只做静态图片或下拉列表。
6. 显示实际音名、八度信息及和弦内音程角色。
7. 单独修改一个位置的一种乐器，其余内容保持。
8. 保存整个材料，重新打开后完整恢复。
9. 把当前材料排版为练习页，通过浏览器打印或另存为 PDF。
10. 中文界面，桌面与手机浏览器均可使用，无广告。

### 2.2 本轮不实现

- 演奏评分、麦克风识别、MIDI 输入识别。
- 打卡、经验值、关卡、考试、自动安排一年的练习课程。
- 现成歌曲搜索、歌词、自动扒谱、音频分析。
- AI 生成进行、自动作曲、复杂声部连接优化。
- 用户注册、云同步、支付、社交功能。
- 原生手机 App、应用商店发布。
- 所有乐器、特殊调弦、变调夹、左手吉他模式。
- 穷尽全部和弦与指型，或承诺所有预置都适合所有人的手。

## 3. 核心概念与术语

| 概念 | 定义 | 例子 |
| --- | --- | --- |
| 进行模板 | 与具体 Key 无关的和弦顺序及默认性质 | ii7–V7–Imaj7–vi7 |
| 和弦位置 Slot | 进行中一个独立、可编辑的位置；同名和弦出现两次仍是两个 Slot | 第 2 个 G7 |
| Key | 本材料的调性设置 | C major |
| 和弦定义 | 根音与和弦性质，表达和声意图 | Cmaj7，构成音 C E G B |
| Voicing | 一次实际演奏的音高组合，包含八度、排列与重复／省略 | C3 E3 B3 E4 |
| 吉他指型 | 实现某个实际 voicing 的弦与品位置 | 六根弦各自静音／空弦／按品 |
| 练习材料 Sheet | 进行、Key、每个位置已选／自定义的两种乐器 voicing，加上标题与显示设置 | 我的 ii–V–I 第 2 版 |

重要：吉他和钢琴不必弹完全相同的音高排列。它们共享和弦定义，各自维护实际 voicing。

## 4. 主要使用流程

1. 打开应用，看到一份可直接操作的四和弦示例。
2. 选择预置进行，例如 ii7–V7–Imaj7–vi7。
3. 选择 C 调，显示 Dm7–G7–Cmaj7–Am7。
4. 按需修改某个和弦性质，例如 Dm7 改为 Dm9；其他位置不变。
5. 每列查看该位置的级数、实际和弦、吉他图、钢琴图。
6. 分别切换吉他与钢琴的候选 voicing。
7. 点击编辑吉他图，将某根弦静音、改品位，或改变某音；点击钢琴键添加／移除音。
8. 看到图和音程标注即时更新；原和弦名称保留。
9. 输入标题，保存为一份材料；也可另存副本。
10. 进入打印预览，选择双乐器／仅吉他／仅钢琴，打印或另存为 PDF。
11. 下次打开已保存材料，继续编辑其中一个位置。

## 5. 界面与信息架构

### 5.1 页面建议

第一版两个主要视图即可：材料编辑页、我的材料。打印使用独立视图或专用打印样式。

材料编辑页顶部放标题、保存状态、Key、进行选择、显示选项和打印入口。主体按和弦顺序排列，每个和弦作为一列卡片。

每列由上到下：

1. 罗马数字级数与和弦性质选择。
2. 实际和弦名称。
3. 理论构成音，简洁显示。
4. 吉他图、候选切换、编辑／重置。
5. 钢琴图、候选切换、编辑／重置。
6. 实际音列表、必要的省略／额外音提示。

默认四列，桌面可同时比较四个和弦。手机上提供横向滚动或适合阅读的逐列布局；禁止为了塞进四列把琴键与指板压缩到不可操作。

### 5.2 视觉参考

参考 Oolimo 的信息表达：同时呈现级数、实际和弦、指板音名、每根弦的和弦音程角色。采用自己的布局、绘图和颜色，不复制网站代码或私有数据。

默认界面清爽、文字易读、操作明确。推荐浅色工作区，保证打印时无需大面积背景。英文音乐符号保留，按钮与说明用中文。

根音、其他和弦音、额外音可使用一致颜色；必须同时有文字或形状标识，不能只靠颜色区分。编辑态与普通查看态要明显区分。

## 6. 功能要件

### F01 进行模板与自定义进行 · P0

- 提供至少 8 个独立模板，见第 10 节。
- 支持选择模板；支持逐个编辑级数及和弦性质。
- 默认 4 个位置；支持添加、删除位置，第一版范围 1–8 个。删除最后一个位置需禁用。
- 使用下拉／结构化输入完成编辑即可，不要求开发复杂的自由文本解析器。
- 常用半音变化级数至少支持 ♭II、♭III、♭VI、♭VII，底层允许 degree 1–7 与 accidental -1/0/+1。
- 每个 Slot 使用稳定 ID；同一个和弦重复出现时可以有不同弹法。
- 切换整个模板不得静默丢失当前编辑；若存在未保存变化，提供保存／放弃／取消，或先可靠自动保存草稿再切换。

### F02 Key 与和弦性质 · P0

- 第一版的级数坐标统一采用“大调音阶相对主音”的 1–7，即半音 [0,2,4,5,7,9,11]；和弦性质显式记录。不要同时混用自然小调相对级数。
- Key 支持 12 个主音。为避免无谓歧义，首版以 major 为默认模式，可用 vi 为起点表达相对小调进行。
- 此约定属于首版范围，不宣称覆盖所有古典罗马数字分析法。界面帮助中简短解释。
- 和弦类型至少支持：major、minor、dim、aug、sus2、sus4、7、maj7、m7、mMaj7、m7b5、dim7、6、m6、add9、9、maj9、m9。
- 提供“三和弦／七和弦／九和弦”快捷方案，仅作为明确规则下的批量编辑；不能把所有和弦后缀统一拼接为 7 或 9。
- 快捷方案最低覆盖自然大调七级的基础三和弦和七和弦；九和弦仅给 major→maj9、minor→m9、dominant→9 的明确映射，dim、aug、sus 等不自动转换并说明哪些位置未变。
- 自定义性质覆盖快捷方案的默认值。像 vi–viMaj7–vi7–vi6 的线条变化模板直接保存显式性质。
- 六和弦首先作为逐和弦性质选择，不强行提供全局“全部变六和弦”。

### F03 吉他预置 voicing · P0

- 标准六弦调弦 E2 A2 D3 G3 B3 E4，内部按低音第六弦到高音第一弦存储。
- 每条数据包含六个绝对品位；-1=不弹、0=空弦、1–24=实际品位。
- 同一个和弦提供多个候选，候选显示位置／最低按弦品位及音程信息。
- 可显示指法数字与横按，但自定义编辑后旧指法可能失效：自动清除失效指法，不能把旧手指数字继续当作正确结果。
- 候选切换只影响当前 Slot 的吉他数据。
- 无候选时明确显示“暂无预置，可自行编辑”，仍可创建指型；不能临时拿其他和弦的图来填充。
- 区分“人工筛选预置”与“规则生成候选”，不把仅数学有效的组合标为经过人工确认。

### F04 吉他图直接编辑 · P0，核心

- 查看态与编辑态分开，避免练习浏览时误触。
- 编辑态点击某根弦／品位置，即将该弦设为该品位；再次点击已选位置可将该弦静音。
- 每根弦最多一个实际发声音；顶部提供明确的 X／0 控件，方便切换不弹和空弦。
- 支持查看／移动指板窗口，编辑 0–24 品。绝对品位为事实来源，窗口起始品只是显示设置。
- 设定精确品位的辅助输入可用于手机、键盘操作和无障碍访问。
- 编辑后立即重新计算六根弦的实际音高、音名、最低音与相对和弦根音的角色。
- 能把任意一根弦静音来省略一个音；如果其他弦仍弹相同音，不能误报该和弦音已完全省略。
- 允许跨度大或不常见的自定义弹法，提供非阻断提示，不强制改回预置。
- 根音位于中间弦或根音被省略时，也要正确显示；最低音不必等于根音。
- 至少提供当前编辑会话的撤销／重做、恢复到选中预置；恢复有自定义变化时需可撤销。

### F05 钢琴预置与直接编辑 · P0，核心

- 内部记录实际 MIDI 音高，不仅是 pitch class。C4=60。
- 默认可编辑音域 C2–C6（MIDI 36–84），键盘可横向滚动，所有已选音都可找到；窗口变化不得删除窗口外的音。
- 图上点击未选琴键添加，点击已选琴键移除；同一 MIDI 音只保存一次，不同八度同名音允许并存。
- 通过“左手／右手”编辑工具分配音。选择已有另一只手的琴键时可转移归属，不能保存相同音同时属于两只手的重复记录。
- 左右手用文字／形状及颜色辅助区分；打印仍可辨认。
- 每个音显示音名与八度，能查看相对当前和弦的角色；可切换简洁音名模式与音程模式。
- 同一个和弦至少有多个配音候选，例如紧密排列、转位、开放排列或简单左右手组合，具体覆盖以第 10 节为准。
- 选择某个钢琴候选不改变吉他；手动编辑不自动移动其他音。
- 支持撤销／重做与恢复预置。
- 允许暂时选零个音，显示“尚未选择音符”；不崩溃，不偷偷添加默认音。

### F06 音名、音程与和弦意图 · P0，核心

- 和弦定义与实际 voicing 独立存储。编辑图不自动覆盖和弦名称。
- 用户选 Cmaj7 后去掉 G，仍显示 Cmaj7，并可提示“省略五音”；禁止自动改名成其他和弦。
- 加入 D 时可标记为相对根音的 9，提示“额外音：D（9）”；用户可自行把定义改成 Cmaj9，也可保留 Cmaj7 标题。
- 实际音重复时逐弦／逐琴键展示，和弦完整性检查按 pitch class 去重。
- 音名按和弦拼写处理，例如 C7 的七音为 B♭，Cmaj7 为 B，Cdim7 中的减七音应能表示为 B𝄫或 Bbb，不能全部粗暴转换为升号。
- 音程角色按和弦定义解释：Cadd9 中 D 是 9，Csus2 中 D 是 2；不能只靠 MIDI 音高差猜 2／9，也不能把实际处于低音区的九音一律改标 2。
- 和弦外的音若有多种解释，按确定的默认拼写显示，并注明是“额外音”；不需要自动完成完整和弦分析。
- 音程中文对应至少包含根音、小三音、大三音、纯五音、降五音、六音、小七音、大七音、九音。
- 统一标准符号采用 1、♭3、3、5、♭7、7、9 等；若复刻 Oolimo 的替代记号，只能作为显式显示偏好，不能在同一模式混用 7 表示小七音又表示大七音。
- 额外音、缺失音、无根音、最低音信息是说明，不是评分或禁止保存的错误。

### F07 修改和弦／调性时的数据规则 · P0

修改和弦性质会改变候选集合，但不能静默丢失手工数据：

- 无自定义变化：选取新和弦对应的默认候选，或保留有效的来源模板。
- 有自定义变化：提供“保留实际弹法并重新标注／替换为新预置／取消”。选择仅作用于这个 Slot。

变更 Key 前先计算整体变更预览，采用事务方式：取消或失败不改动原材料。

- 钢琴：按主音变化的最短有向半音距离移调（±6 的平局固定一种方向）；保留相对排列与手分配；可让用户选择上下八度修正；超出支持音域时不静默截断音。
- 吉他：所有发声弦按同一半音差平移，静音弦不变；只有结果全部落在 0–24 品时才能作为直接移调结果。空弦不能错误地固定在原音。
- 吉他无法直接移调时，允许用户为受影响位置明确选择“换用该和弦的新预置”或取消；不能只改和弦名字而让旧图继续显示。
- 预置替换会失去原自定义弹法，必须在预览中标明受影响位置，确认后才应用；原材料可撤销或由草稿备份恢复。
- 升降号等音拼写改变但主音实际不变时，音高不移动，只更新音名。

### F08 保存与材料管理 · P0

- 无需登录，本地 localStorage 或 IndexedDB 保存。首版数据量可选 localStorage。
- 保存实际 positions／notes 的完整快照，不能只保存预置的 ID；库更新或预置删除也不能导致材料丢失。
- 支持保存、另存副本、改标题、打开、删除；删除需确认且不影响其他材料。
- 自动保存当前草稿，刷新后可恢复；“草稿”和“已命名材料”在状态上区分。
- 保存状态明确显示；浏览器存储满或不可用时显示失败，不能假装已保存。
- 提供 JSON 导出／导入，作为备份和跨设备手动转移；导入做 schema 和范围校验，包含 schemaVersion。
- 用户输入作为文本处理；JSON 导入不执行代码，不直接注入 HTML。

### F09 打印与 PDF · P0

- 浏览器打印／另存为 PDF 即满足第一版 PDF 要求，不必开发服务端 PDF 生成。
- 可选双乐器、仅吉他、仅钢琴。
- 4 个和弦的默认双乐器材料，目标是 A4 横向一页：列是和弦，上排吉他、下排钢琴；显示标题、Key、级数、和弦名和必要图例。
- 使用当前编辑状态，包括自定义、省略、额外音、静音与左右手信息；禁止在打印时重新生成默认 voicing。
- 打印样式移除按钮、导航、滚动条和大面积背景，避免图被裁切；文字与图均清晰。
- 5–8 个和弦可按每页最多 4 列分页。较宽钢琴音域不能被强制挤压成不可读；可显示拆分的左右手键盘并标八度，或扩大单卡片版面后分页。
- 单个图不跨页截断；黑白打印仍能凭音名和标记理解。
- 明确按钮名称为“打印／另存为 PDF”，不误称已经下载 PDF。

### F10 单图导出与试听 · P1

- SVG 单图导出优先于 PNG；整页 PDF 已由 P0 覆盖。
- 可用 Web Audio 为当前实际音高提供简单试听，必须由用户点击触发。
- 试听若实现，必须播放编辑后的实际音，不得固定播放和弦根位。
- 本轮不需要节奏播放器或仿真乐器音源。

## 7. 音乐与数据正确性规则

### 7.1 根音计算

内部 pitch class 采用 C=0 到 B=11。degree=1–7，基于大调相对主音的半音表 [0,2,4,5,7,9,11]；再加 accidental。实际根音为主音加级数偏移并对 12 取模。

性质独立于 degree 保存，例：degree=5、quality=7 得属七和弦；degree=1、quality=maj7 得大七和弦。不要把“七和弦”当成单一的后缀。

显示级数时，major 家族大写、minor 家族小写，dim 加 ° 或 ø 等标识；特殊符号用统一格式化函数生成。内部不要仅依赖大小写还原全部性质。

第一版不支持副属和弦 V/ii 等复合级数语法；可通过具体 degree、accidental、quality 表达相应音高关系，但不宣称保留完整功能分析。

### 7.2 吉他音高计算

低到高六弦标准 MIDI：[40,45,50,55,59,64]。发声音高=空弦 MIDI+绝对品位；静音 -1 没有音高。声音排序按实际 MIDI，不按弦号猜测最低音。

导入第三方数据时，必须用适配器核对弦序、baseFret 与相对品位等字段，转换到本项目的绝对品位模型。不能原样假设所有库都从第六弦开始。

### 7.3 和弦构成与实际音分离

和弦构成记录带拼写意义的音程，例如 1P、3m、5P、7m、9M。用于检查的 pitch class 集合与展示用音名／音程标记分开。

九和弦等扩展和弦的实际 voicing 可省略部分音；可以重复根音或其他音。不要用“必须包含全部构成音”来过滤掉所有常见配音。预置需要记录省略与用途说明。

有效数据范围检查和音乐解释分开：品位越界、MIDI 非整数属于数据错误；省略根音或加入额外音是允许的音乐选择。

## 8. 建议数据结构（TypeScript）

以下是可实施方向，可在保持语义的前提下简化。

```ts
type Quality =
  | 'major' | 'minor' | 'dim' | 'aug' | 'sus2' | 'sus4'
  | '7' | 'maj7' | 'm7' | 'mMaj7' | 'm7b5' | 'dim7'
  | '6' | 'm6' | 'add9' | '9' | 'maj9' | 'm9';

interface ChordSpec {
  degree: 1 | 2 | 3 | 4 | 5 | 6 | 7;
  accidental: -1 | 0 | 1;
  quality: Quality;
}

interface ProgressionTemplate {
  id: string; // 稳定 ID；不把显示用罗马数字字符串当唯一主键
  nameZh: string;
  chords: ChordSpec[];
  tags: string[];
  source?: string;
}

interface GuitarVoicing {
  id: string;
  nameZh: string;
  tuningMidi: [number, number, number, number, number, number];
  frets: [number, number, number, number, number, number];
  // 低音第六弦到高音第一弦；-1 静音、0 空弦；其余为绝对品位
  fingers?: (0 | 1 | 2 | 3 | 4 | null)[];
  barres?: { fret: number; fromString: number; toString: number }[];
  // fromString/toString 统一采用音乐习惯弦号 1–6，适配器与渲染器须明确转换
  sourceId?: string;
  reviewed: boolean;
  descriptionZh?: string;
}

interface PianoVoicing {
  id: string;
  nameZh: string;
  notes: { midi: number; hand: 'left' | 'right' }[];
  sourceId?: string;
  reviewed: boolean;
  descriptionZh?: string;
}

interface ChordSlot {
  id: string;
  chord: ChordSpec;
  guitar: GuitarVoicing; // 完整快照
  piano: PianoVoicing;   // 完整快照
  guitarPresetId?: string;
  pianoPresetId?: string;
  guitarEdited: boolean;
  pianoEdited: boolean;
}

interface PracticeSheet {
  schemaVersion: 1;
  id: string;
  title: string;
  key: { tonic: string; mode: 'major' };
  templateId?: string;
  slots: ChordSlot[];
  display: {
    labels: 'notes' | 'intervals' | 'both';
    instruments: 'both' | 'guitar' | 'piano';
  };
  createdAt: string;
  updatedAt: string;
}
```

音名、理论构成音、角色、最低音等均从当前数据派生，避免在多处手动维护造成不一致。可以缓存，但必须有统一计算入口。

### 8.1 一个可核验的数据例子

和弦定义：C 调 ii7，即 Dm7。

吉他 frets = [-1,5,7,5,6,5]。实际音按弦序为静音、D3、A3、C4、F4、A4；角色是 X、1、5、♭7、♭3、5。

钢琴可以使用左手 D3（50），右手 A3（57）、C4（60）、F4（65）。两种乐器都表达 Dm7，但实际排列不同。

不能把此示例扩展成“所有和弦都复制这个指型改名字”。每条数据都要重新核对音高。

## 9. 技术方案建议

### 9.1 最小架构

- React + TypeScript + Vite，纯客户端 SPA。
- 采用当前环境可用且相互兼容的稳定依赖，锁定 lockfile；不必追逐最新版本。
- React 本地状态／reducer 足够；若状态复杂可选轻量状态库，不引入服务端框架。
- Tonal 可作为音符、和弦、音程与移调工具；用薄适配层封装，项目的级数约定和拼写规则仍须测试。
- 自绘 SVG 吉他指板、SVG 或 HTML/SVG 钢琴键盘。若现有绘图库难以支持点选编辑、音名和音程，直接实现小型组件，不强行套库。
- localStorage / IndexedDB 存储；JSON 做交换格式；浏览器原生打印做 PDF。
- 使用 CSS Grid 排版；所有文字集中于中文文案对象，便于以后补语言。
- 本轮不需要后端、数据库、密钥、云服务。

未来移动端优先可考虑 PWA 或 Web 容器，但本轮只保留音乐模型与 UI 分离，不预先实现原生工程。

### 9.2 推荐模块

```text
src/
  domain/        # chord、degree、interval、transpose、validation
  data/          # progressions、guitar、piano、source metadata
  adapters/      # tonal／第三方和弦数据适配
  components/    # GuitarDiagram、PianoKeyboard、ChordCard 等
  features/      # editor、sheet-library、print-view
  storage/       # schema、导入导出、持久化
  styles/        # 工作区与打印样式
```

目录为建议。保持业务逻辑可单测，避免把所有规则写进一个 JSX 文件。

## 10. 第一版素材要求与来源策略

### 10.1 预置进行

至少提供以下 8 个，所有性质显式存储，默认在 C 调可核对：

| ID 建议 | 级数 | C 调示例 |
| --- | --- | --- |
| pop-1564 | I–V–vi–IV | C–G–Am–F |
| pop-6415 | vi–IV–I–V | Am–F–C–G |
| turnaround-2516 | ii7–V7–Imaj7–vi7 | Dm7–G7–Cmaj7–Am7 |
| turnaround-1625 | Imaj7–vi7–ii7–V7 | Cmaj7–Am7–Dm7–G7 |
| descending-4362 | IVmaj7–iii7–vi7–ii7 | Fmaj7–Em7–Am7–Dm7 |
| minor-line | vi–viMaj7–vi7–vi6 | Am–AmMaj7–Am7–Am6 |
| borrowed-7411 | ♭VII–IV–I–I | B♭–F–C–C |
| minor-6425 | vi7–IVmaj7–ii7–V7 | Am7–Fmaj7–Dm7–G7 |

注意 minor-line 中 viMaj7 表示“小三和弦＋大七音”，属于 minor-major seventh，对应 Quality 中的 'mMaj7'，不能误当 major maj7。若实施时使用不同类型命名，也要保留其准确语义。

模板可以按“基础／七和弦／色彩变化”等中性标签分类，不需要声称某个进行专属于 R&B 或 Jazz。

### 10.2 Voicing 覆盖目标

- 核心质量 major、minor、7、maj7、m7：12 个根音，每种每根音至少 3 个吉他候选、3 个钢琴候选。可由明确可移调模板生成，不要求手录每个 Key。
- 9、maj9、m9、6、m6、m7b5：目标每根音至少 2 个候选；如果有实际音域或指型限制，明确可用范围，允许手工补充。
- minor-line 涉及的 mMaj7：至少确保 C 调默认模板所需的 AmMaj7 在两种乐器上有可用候选；理想情况使用可移调模板覆盖所有根音。
- 其他支持的质量允许先只有少量候选或显示“暂无预置”，但必须支持正确构成音计算与手动编辑。
- 为默认 C 调所有模板逐一检查；不能默认打开某模板就大量空白。
- 这些数量是工作目标，不允许为凑数重复同一个弹法、胡乱组合或标注虚假“人工验证”。覆盖不足时保留真实数据并在交付报告说明。

## 11. 非功能要件

- 中文默认，音乐字母与符号准确；具备键盘焦点与基础无障碍标签。
- 375px 手机宽度下可完成核心编辑；点击区域建议至少 44px。吉他／钢琴图可横向滚动，不将小屏作为禁用理由。
- 图形优先矢量，放大与打印保持清楚。
- 编辑反馈即时；数百条本地候选不能导致明显阻塞。无必要不加载成千上万条无关记录。
- 正常运行不依赖第三方服务在线请求；依赖安装后的基本功能可离线使用，不要求首版 Service Worker。
- 用户数据不上传服务端，无分析跟踪；持久化失败必须可见，并提供 JSON 导出自救。
- 自定义标题长文本、特殊字符不能破坏布局或打印。

2. 对所有内置预置做自动数据检查：范围、实际音、角色、声明省略／额外音是否一致。

## 13. 实施计划

### 阶段 1：可运行骨架与音乐模型

创建项目、类型、和弦公式、级数计算与音名／音程适配。实现一个默认四和弦进行；用实际数据展示吉他与钢琴图。

完成标志：项目可启动，默认八张图表达正确的实际音，核心音乐纯函数通过测试。

### 阶段 2：直接编辑闭环

实现吉他点击选品、X／0、窗口移动；钢琴点击选音与左右手；即时更新标记；撤销／重做。

完成标志：用户能够从预置出发，省略五音、添加额外音，并看到准确变化。此阶段优先级高于扩大素材库。

### 阶段 3：模板、候选与变更规则

加入 8 个模板、质量选择、候选切换、Key 变更事务、自定义保护；整理并检查第一版素材。

完成标志：同一进行可以生成多组弹法，单列修改不会串改其他内容，移调不产生“名字变了图没变”的错误。

### 阶段 4：持久化与打印

实现草稿、材料管理、JSON 导入导出、打印模式与 A4 排版。

完成标志：保存后重开与打印都忠实恢复自定义实际音。

### 阶段 5：验证与交付

跑必要测试和构建；检查手机与打印；修复数据、布局与状态问题；编写运行说明和已知限制。

本计划是实施顺序，不承诺在固定小时内完成。若执行窗口有限，减少候选数量或省略 P1，保住 P0 核心闭环，并如实报告未完成项。

## 14. 风险与处理

| 风险 | 处理 |
| --- | --- |
| 把和弦字典当成实际 voicing 数据 | 保存实际音高／品位，构成音仅用于解释 |
| 库的弦序／品位约定不同 | 适配器统一格式，用已知指型做测试 |
| 拼写显示正确但实际音错 | MIDI/pitch class 计算与展示拼写同时校验 |
| 编辑后只更新图，没有更新保存或打印 | 使用统一事实数据源，查看与打印共享派生逻辑 |
| 半途扩展为课程、游戏或伴奏播放器 | 严格按 P0 实施，P1 完成后再考虑 |
| 自定义数据被 Key／质量变更覆盖 | 预览、明确选择、事务与撤销 |
| 自动生成的吉他数据可弹性差 | 优先可信来源与少量筛选，标明 generated/reviewed |
| 依赖或网络卡住进度 | 可替换适配层、本地种子数据，不依赖在线 API |
| 手机图太小无法编辑 | 横向滚动与辅助输入，图可读优先于强塞布局 |

## 15. 第一版完成定义

第一版可以交付的最低条件是：

- 一个本地可运行的真实应用，有启动指令与 lockfile。
- 能从级数与 Key 得到正确和弦，选择并编辑两种乐器图。
- 实际弹出的音、音名与角色一致；省略音不导致意图名称被改写。
- 保存／重开和打印完全保留当前自定义结果。
- 基础模板可用，候选覆盖不足有真实说明。
- 关键测试与生产构建通过，或报告可复现的阻塞与未执行项。
- README、实现状态与第三方数据说明齐全。

静态页面、只能切换图片的演示、没有保存的编辑器、使用占位图的界面，都不算实现完成。
